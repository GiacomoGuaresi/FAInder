# Data

The app shows the places listed in [`data/beni-fai.json`](../data/beni-fai.json). The file is generated by [`scripts/fetch_beni_fai.py`](../scripts/fetch_beni_fai.py).

## Sources

Two public endpoints of the FAI platform, read without authentication:

| Endpoint | What it lists |
| --- | --- |
| `https://platform.fondoambiente.it/api/luoghi/beni` | FAI properties |
| `https://platform.fondoambiente.it/api/luoghi/faixme` | offers for FAI members, each tied to a place |

The script asks for 300 items per page and waits 0.3 seconds between pages. A full run is a handful of requests.

## What the script does

1. Reads all pages from both endpoints.
2. Keeps one entry per place id; places without coordinates are skipped.
3. Takes the description from `descrizione_html` (tags removed, whitespace collapsed) or, if empty, from `payoff`.
4. Takes the categories from the offer; FAI properties get the single fixed category `Bene FAI`.
5. Merges the two lists. When a place appears in both, the entry from `faixme` wins, because it carries real categories.
6. Writes the result as indented UTF-8 JSON.

## Format

```json
{
  "id": 12345,
  "title": "Name of the place",
  "lat": 45.1234,
  "lng": 9.5678,
  "url": "https://fondoambiente.it/luoghi/slug-of-the-place",
  "description": "Plain-text description, or null",
  "categories": [{ "id": 8, "name": "Visitare luoghi d'arte" }]
}
```

The `Bene FAI` category has `"id": null`.

## Updates

`.github/workflows/update-beni.yml` runs the script every night at 00:00 UTC (and on manual dispatch) and commits `data/beni-fai.json` only when it changed. This is why most commits in the history are by `github-actions`.

The app downloads the file from the `main` branch of this repository at startup; if the download fails it uses the copy bundled at build time.

To refresh the file by hand:

```bash
pip install requests
python scripts/fetch_beni_fai.py
```
